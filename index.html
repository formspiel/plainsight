Plainsight

A library-agnostic reference documenting expected keyboard operation and screen reader/assistive-technology behavior for common chart types. A sibling project to native-form-elements, same spirit applied to data visualization instead of form controls.

Why not just a data table?

A chart's entire value proposition is letting a sighted user spot a trend, an outlier, a comparison, in under a second — a perceptual shortcut a table doesn't give you. If the "accessible version" of a chart is just a data table fallback, assistive technology and keyboard users get a strictly worse experience: same data, none of the perceptual shortcut.

The goal of this project is charts that are the accessible experience, with a data table as a genuine parallel option for users who want exact values — not an excuse for skipping chart accessibility. Every chart page here builds a real keyboard- and screen-reader-navigable chart first; the data table sits alongside it, not instead of it.

Who this is for

Built as a checklist companion for accessibility testers auditing applications containing charts — and, through them, for developers building charts and designers who need to understand accessible chart design before shipping inaccessible defaults. One canonical reference, shared onward as needed rather than split into separate tracks per audience.
